# Interaction Flow between Fitnet Project and AppHost

## Overview
The **Fitnet** .NET Core library is hosted inside an **ASP.NET Aspire** application (`Fitnet.AppHost`). 
The Aspire host is responsible for wiring up infrastructure (PostgreSQL, Swagger, Swagger UI, etc.) and 
starting the ASP.NET Core Web API that exposes the domain functionality. The API is composed of four bounded‑context 
modules: **Contracts**, **Offers**, **Passes**, and **Reports**. Each module registers its HTTP endpoints and middleware 
into the `IEndpointRouteBuilder` during application startup.

## Startup Sequence
1. **AppHost (Aspire)**
   - Creates a distributed application with a PostgreSQL container.
   - Adds the `Fitnet` project as a service and references the PostgreSQL database for each bounded context.
   - Runs the `Fitnet` project.

2. **Fitnet (ASP.NET Core Web API)**
   - `Program.cs` builds a `WebApplication`.
   - Registers core services: Controllers, Swagger, EventBus, Validation, Clock, and the four bounded‑context services via extension methods (`AddContracts`, `AddOffers`, etc.).
   - Configures middleware pipeline: Swagger UI (dev), API documentation, module middlewares (`UseContracts`, `UseOffers`, …), HTTPS redirection, authorization, error handling.
   - Maps the module endpoint groups via `app.MapContracts()`, `app.MapOffers()`, etc.
   - Starts listening for HTTP requests.

### Example Flow: Prepare Contract
1. **Client** sends `POST /api/contracts/prepare`.
2. `PrepareContractEndpoint.MapPrepareContract` receives the request and validates it.
3. Calls `Contract.Prepare` to create a new aggregate, applying business rules via `BusinessRuleValidator`.
4. Persists the aggregate via `ContractsPersistence` (EF Core `DbContext`).
5. Returns `201 Created` with the new contract ID.

### Example Flow: Sign Contract
1. **Client** sends `PATCH /api/contracts/sign/{id}`.
2. `SignContractEndpoint.MapSignContract` fetches the aggregate, validates the request, signs the contract, and saves changes.
3. Publishes a `ContractSignedEvent` via the `IEventBus`.
4. Returns `204 No Content`.

## Cross‑cutting Concerns
- **Event Bus**: Implemented as `InMemoryEventBus` in `Fitnet.AppHost` (see `Fitnet.AppHost.csproj` and its dependencies). Events are published after domain state changes.
- **Validation**: `FluentValidation` integrated via `RequestValidationApiFilter`.
- **Error Handling**: Global exception handler (`GlobalExceptionHandler`) returns standardized error responses.
- **Clock**: `TimeProvider` abstraction used to allow deterministic testing.

## Summary
- The **AppHost** launches the **Fitnet** ASP.NET Core API as a micro‑service.
- **Fitnet** registers services and maps HTTP endpoints for each bounded context.
- HTTP requests flow through ASP.NET Core middleware into module‑specific handlers that interact with EF Core repositories and publish domain events.
- The system follows Clean Architecture and DDD principles, with clear separation of concerns and vertical slices per bounded context.
